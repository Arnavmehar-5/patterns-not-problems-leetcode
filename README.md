## 📁 Repository Structure

The `C++` folder contains solutions I've written and tested myself in VS Code, organized loosely by pattern rather than by problem number — the idea is to try and build some intuition for why a pattern works, not just memorize a fix for one problem.

## ▶️ Running the Code

Each solution is a standalone `.cpp` file. To compile and run any of them locally in VS Code (or any terminal with `g++` installed):

```bash
g++ valid-palindrome.cpp -o valid-palindrome
./valid-palindrome
```

Just swap `valid-palindrome` with the name of whichever file you want to compile and run.

## 🎯 Why "Patterns, Not Problems"

It's easy for LeetCode practice to turn into memorizing isolated answers. I'm trying to organize this repo the other way around — by pattern (two pointers, sliding window, backtracking, etc.) — so each solution also works as a note on the underlying technique, in case it's useful for revision or for anyone else trying to reason through problems rather than just copy code.

## 🌱 Still Learning

I'm not claiming to have this all figured out — this repo is as much a part of my own learning process as it is something I hope can help others. I'll keep adding, revisiting, and probably rewriting solutions as I understand patterns better over time.

If you spot a mistake, a better approach, or just have thoughts on how something could be explained more clearly, I'd genuinely love to hear it. Learning out loud like this, with room for feedback, feels like the best way to actually get better — and maybe it helps someone else along the way too.
